# 多 Agent 协作

团队模式是 Micro-Multi 的主要执行方式。主 Agent 负责准备方案和汇总结果；成员分别承担实现、测试、文档或审查。调度器处理并发、依赖、文件归属和重复派发，你决定方案是否执行。

## 检查方案

在输入区选择多智能体协作，说明任务、限制和验收条件。准备阶段，主智能体读取相关资料并编写需求、设计和任务文档；你确认方案前，成员不会启动。

方案卡片列出建议的团队。打开“调整团队”可修改职责、提示词、负责文件和模型。检查分工是否符合任务，是否存在多人同时修改同一文件的冲突，再点击“确认执行”启动当前显示的版本。新任务或新一轮反馈会生成另一版方案，需要再次确认。

卡片出现时，后台可能仍在保存规划轮。确认操作会先等待保存完成，再核对服务端版本。本地缓存落后不会阻止有效方案执行；若服务端确实有新版，卡片原地更新，审核后再次确认即可。批准过且已启动的版本不能再次执行，也不会因旧批准请求重新进入规划。

## 并行和依赖

独立任务可以在并发上限内同时执行。需要前置结果的任务声明 `depends_on`，等待前置报告；前置失败则停止依赖任务。不要把有先后关系的工作为了“并行”拆成同时写入。

例如接口成员修改 `api.py`，文档成员修改 `docs/api.md`，两者可以独立工作。集成测试成员依赖接口实现，应等接口报告后再执行。各成员通过 `owned_paths` 声明负责文件；路径预留与锁协调共享工作区。同一文件的不同阶段可以由有依赖关系的成员接续处理。

启用的 DeepSeek Harness 插件工具、MCP 与命令工具可供主 Agent 和成员使用，不需要为每个成员安装一套插件。成员仍按自己的模型配置和当前权限执行。插件接口见[原生 dsh 插件](NATIVE_CORDIS.zh-CN.md)。

## 跟踪执行

成员默认跟随主模型，也可以使用你单独指定的模型。团队视图展示任务、状态和报告，工具记录展示文件操作、命令、扩展调用及审批情况。

执行过程中可以补充指导。需要检查当前状态时暂停对话，需要结束执行时停止对话。主智能体可以移除失败成员再尝试其他办法；移除会取消该成员的任务并释放文件预留。

## 检查结果

成员返回报告后，查看实际文件、差异和验证输出。完成报告不能代替通过的测试或审查。发现遗漏时，在后续消息中说明，并检查下一版方案。

方案记录保存在工作区的 `.masp/team-plans/`，方案卡片保留在对话历史中。[任务示例](../PRODUCT_DEVELOPMENT_SPEC.zh-CN.md)展示了实现与测试成员的分工方式。

成员不是越多越好。短任务用主 Agent 即可；团队适合有明确职责和可并行工作的任务。更多成员可能增加模型费用，参见[Agent 设计与取舍](AGENT_DESIGN.zh-CN.md)。
