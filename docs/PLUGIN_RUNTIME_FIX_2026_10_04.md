# 通用 DSH 插件宿主修复（2026-10-04）

## 根因与修复

- npm 安装包与 Cordis 服务激活是两个步骤。宿主过去只启动部分基础服务，现在根据插件的实际 `inject`，从官方基础组合和已安装依赖发现提供者，递归激活服务及配置选择的存储后端。服务加载不包含 `dsh-all-usage` 等插件名分支。
- 服务目录按需读取，不执行整个插件目录的模块初始化。基础组合决定官方提供者和默认配置；新插件的依赖元数据进入同一目录。插件之间先完成挂载，再解析未满足的服务。
- 设置页支持插件自己的页面，也支持自动 Config 表单。自动表单反序列化真实 Schemastery schema，通过原生 settings Remote 保存；基础字段直接编辑，复杂字段支持 JSON。
- 插件通过客户端声明的 slot 注入点贡献的新入口由宿主声明和显示。侧栏入口同时可在插件详情中使用，在对话界面接入应用 shell。
- 客户端发布包压缩后的 factory 参数不一定叫 `require`。构建器识别实际参数名，避免漏打包 React 等模块。
- 配置更新等待完整 Cordis waterfall 和插件重启；激活成功后才原子保存。启动或保存失败恢复旧配置。挂载失败清理新增插件和设置目录。
- SDK 快照过去直接复制本机 node_modules，并以整份 lockfile 为标识。现在根据 SDK 包版本、来源和完整性建立基准，从校验通过的 npm 包提取代码；逐文件校验快照。无关依赖变化不重置 SDK 基准，插件改写本机 SDK 或快照不会被自动接纳。
- timer、session-query、workspace、storage、JSON 后端及 domain 服务作为明确的生产依赖进入桌面包。

## 验证范围

- 新建无专用适配的插件，要求 `sessionQuery`、`workspaceRegistry`、`timer`、`storage`，真实激活并调用工具。
- 设置 Remote 更新、立即调用、宿主重启恢复；故意制造启动失败，确认旧配置及工具恢复；故意制造服务缺失，确认回滚新增目录。
- 验证发布版本 `dsh-all-usage@1.1.17` 的真实宿主激活和客户端“用量统计”入口渲染。
- 验证压缩 factory、新 slot、自动表单、异步设置页和对话贡献。客户端检查使用代码渲染断言，没有模拟点击。
- 验证 SDK 原文件被修改、无关锁文件内容改变及快照被修改时仍使用校验通过的包源码。

## 通用兼容契约

插件通过 Cordis `inject` 声明服务，通过 npm 依赖或 DSH 基础组合提供实现；配置使用 Config schema，客户端使用声明的贡献点。宿主按照这些契约完成自动加载、设置和生命周期处理。缺少真实提供者或插件自身启动抛错时返回具体依赖或启动诊断并回滚，不伪造服务或把失败标记为安装成功。
