# 连接模型

Micro-Multi 使用你配置的模型服务。开始对话前，准备该服务的 API 地址、模型 ID 和凭据。接口需要支持应用使用的 OpenAI 兼容聊天请求，仅凭服务的名称不能判断是否兼容。

## 添加并测试连接

打开“设置”，选择“模型”，再进入“添加或编辑模型”。先为连接取一个便于在输入区识别的名称，然后填写服务给出的 API 地址、准确的模型 ID 和密钥。如果服务文档给出的基础地址是 `https://api.example.com/v1`，应填写这个地址，而不是网页聊天页面的网址。

保存后点击“检测连接”。失败时先看返回的信息：认证失败、模型不存在和服务器无法连接，分别需要检查不同的配置。[常见问题](TROUBLESHOOTING.zh-CN.md)介绍对应的处理方法。

## 为任务选择模型

在对话输入区选择已保存的模型配置。名称用于识别本地配置，模型 ID 才是发送给远端 API 的值。因此，同一服务可以保存多个连接配置，也可以为不同任务使用不同服务。

团队模式下，成员默认跟随主模型。确认方案前，可以在团队编辑器中为成员另选模型。应选择支持该成员所需工具调用的模型；插件提供的模型还可能需要在插件详情中配置。

## 请求参数与凭据

模型表单还提供 temperature、top-p、最大输出 token 数和请求超时。使用供应商支持的参数；输出上限控制回复长度，并不等于模型的完整上下文窗口。如果回复被截断，先检查响应和输出上限，再决定是否调整。

模型配置的 API 密钥保存在系统凭据库，不写入项目文件。Linux 需要运行并解锁 Secret Service 凭据库。源码部署也可通过 `MASP_MODEL_BASE_URL`、`MASP_MODEL_NAME` 和 `MASP_MODEL_API_KEY` 配置环境模型，参见[部署](deployment.zh-CN.md)。
