# DSH 通用插件运行层与团队执行修复

## 运行层修复

统一处理 DSH 协议和版本差异，不按第三方插件名称建立适配分支：

- 原生 `webserver/index-inject` 和 `webServer.tapIndex` 注入按官方渲染顺序进入页面，覆盖没有 client entry 的挂件、脚本、样式和 HTML。
- Bundle 对既有条目的补丁从官方 `dsh-base` 组合解析；已有核心实例共享，避免重复注册服务。仅修改既有 LLM 条目的插件也能提供配置和模型目录。
- 旧版 `settings.register` 映射为实际 Schema 配置条目；避免重复注册同一命名空间。设置区覆盖 section、page、plugin item、plugins tab、general item 和 action；只有输入区/overlay 的客户端可显示原生入口。
- 旧版 ModuleLoader 图标数字尺寸名称按统一名称规则解析到当前 primitives 导出。插槽错误可见，不再无提示地显示空白。
- 插件 HTTP 使用原始流代理，支持持续响应、二进制和重复响应头；自定义 RPC channel 可返回异步流。设置读取复用组合 Host，避免每打开一页重启全部插件。
- 设置、模型同步和资源加载都以实际 Host 能力为准；模型同步入口只显示在拥有模型 provider 的插件上。

发现插件改写了 19 个应用 SDK 包，其中审批被改成无条件放行。已从对应官方版本恢复依赖，增加统一 framework source snapshot：原生 Host 在导入前安装加载钩子，客户端编译也读取同一快照。插件仍可注册自己的服务和界面，其对应用 SDK 文件的改写不会改变应用执行器。桌面打包包含锁文件和源码快照。

这属于 SDK 运行稳定性隔离，不是任意 Node 插件的安全沙箱。

## 团队与模型

- 新增成员和生成方案默认跟随主模型；模型生成的创建、调整及批量调度工具不能自动替换成员模型。用户在团队编辑界面手动指定的模型保留并用于实际请求。
- 保存团队同步对话主模型和前端选择器，执行器读取编辑后的配置。
- 同一轮、同一成员、同一任务的异步和同步调度入口共享一次执行。重复派发等待现有操作或复用已完成的真实报告；新任务正常执行，失败可重试，用户移除成员时取消对应操作。新增验收条件明确交由主代理核查，不伪装为已执行。
- 流异常保存具体原因，避免所有错误都只剩 `stream_interrupted`。长度截断和真正断流的恢复仍有边界，不将未完成响应当成成功。

## 实际验证

- Redteam、ModLens、插件市场等设置实际挂载；挂件脚本资源 HTTP 200。未把账户授权、外部服务可用性或所有第三方业务操作等同于已验证。
- 隐藏 Chromium 启动：8 个客户端同时挂载，页面可响应；侧栏和输入区命中正常。聊天、设置和插件接口并行请求全部 HTTP 200，合计 248 ms。
- 原生审批允许、拒绝、取消、并发归属及执行屏障共 7 项通过。屏障测试等待真实执行标记，移除固定睡眠对线程到达顺序的假设，保留原有并行与独占断言。
- 真实模型请求验证普通回复和工具调用均正常结束。
- 真实已编辑团队：主模型与跟随成员使用 `gpt-6-luna`，手动指定成员使用 `gpt-6-sol`。两个成员分别写入文件，主代理读取验证，所有成员及整轮均 completed，没有 stream_interrupted；一次运行 13.17 秒。测试使用独立工作区，没有修改用户项目。
- 静态检查与源码覆盖记录见 `SOURCE_AUDIT_2026_10_04.json`；该记录区分自动逐行读取/解析检查与人工语义检查。
