# 启动后界面阻塞修复

## 根因和修复

插件长期订阅使用 HTTP 流，与聊天、设置及资源请求共用 Chromium 对同一地址的连接池。多个插件同时加载后，后续请求排队，呈现为界面无反应。改为 WebSocket 订阅；保留旧 HTTP 流接口兼容其他调用。服务器验证 Origin、首包大小和握手时间，断开连接取消原生订阅并清理任务。增加 wsproto 依赖，并同步桌面运行时锁与依赖验证。

原生插件首次启动的 body portal 遮罩覆盖了整个应用。将插件 body portal 放入受其生命周期管理的独立层；遮罩背景不拦截主界面，插件卡片控件仍可操作。没有自动同意、写入确认状态或删除插件确认流程。

新聊天没有 session binding 时不渲染严格会话插槽，避免初始化错误。全局下拉增强及翻译观察器不再修改 React 管理的插件控件。客户端资源 URL 加入运行时版本，新增 portal 桥代码参与编译缓存哈希。

## 验证

- 真实 Chromium 隐藏窗口启动及恢复会话，没有模拟点击。7 个已安装插件全部挂载，持续定时读取 DOM 正常；命中检测确认侧栏和输入区不再被全屏插件遮罩截获。
- 在 7 个插件同时挂载后，从同一浏览器并行读取聊天列表、设置和插件接口，全部 HTTP 200，两次总耗时分别为 154 ms、96 ms。
- 8 路 WebSocket 长期订阅并行时 HTTP 请求正常，断开后全部清理；跨域 WebSocket 被拒绝。
- 实际 Cordis/React 组件验证 body portal 所属层、卸载和无会话插槽；完整聊天页面在中英文下验证启动、定时器、DOM 观察器收敛及插件 select 不被全局逻辑改写。
- 针对流、原生协作及新增订阅的 Python 回归：31 项通过。最终全量回归：288 项通过、1 项因系统不允许创建符号链接而跳过（255.99 秒）；Ruff、Mypy 和 JavaScript 语法检查通过。

诊断时一次临时隐藏窗口进程使用了已关闭的标准输出管道，出现 probe-startup.cjs 的 EPIPE 弹窗；该诊断进程已关闭，后续诊断使用文件日志、独立临时用户目录和忽略标准输出。产品代码未引入该临时脚本。


## 新增组件后的输入栏布局

底部工具栏固定单行，使用容器宽度调节间距，空插件插槽不占间距。模型、模式和插件控件可收缩，长名称省略；权限、上下文计数禁止换行，发送按钮保持尺寸。窄容器简化标签，权限按钮保留可访问名称。

真实 Chromium 在加入 Max 强度与速度控件后验证 850、640、480、360 像素输入栏宽度：工具栏无横向溢出、控件同排，插件控件保持在所属区域内；未模拟点击。完整聊天启动测试仍通过。
